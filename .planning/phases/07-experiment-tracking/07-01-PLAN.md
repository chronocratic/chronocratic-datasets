    ```python
    def create_loggers(
        *,

        run_name: str,
        tracking_mode: str = "online",
        persist_artifacts: bool = True,
    ) -> tuple[WandbLogger | TensorBoardLogger, ...]:
    ```

    - If `persist_artifacts` is False, return empty tuple `()`.
    - Always create TensorBoardLogger: `TensorBoardLogger(save_dir=str(run_dir), name="tensorboard")`. This writes to `run_dir/tensorboard/events.out.tfevents.*` (per RESEARCH.md Pitfall 6, isolated per-run).

      ```python
          log_model=False,              # D-07: no checkpoint upload
          save_dir=str(run_dir),
      )
      ```
    - Return `tuple(loggers)` containing TensorBoardLogger always, plus WandbLogger if tracking is not disabled.

    **Private helpers** (all keyword-only `*,`, type-hinted, Google docstrings):

    1. `_find_wandb_logger(*, loggers: tuple[pl.loggers.LightningLogger, ...]) -> WandbLogger | None`:
       Iterates loggers, returns first where `type(logger).__name__ == "WandbLogger"`. Uses type name check (not isinstance) to avoid importing wandb at module level.

    2. `_flatten_dict(*, d: dict[str, Any], separator: str = "_", prefix: str = "") -> dict[str, Any]`:
       Recursively flattens nested dicts. `{"a": {"b": 1}}` becomes `{"a_b": 1}`. Lists use index keys: `{"a": [1, 2]}` becomes `{"a_0": 1, "a_1": 2}`. Handles list items that are dicts by recursing with index prefix.

    3. `_log_config_to_wandb(*, config_data: dict[str, Any], loggers: tuple[pl.loggers.LightningLogger, ...]) -> None`:
       Finds WandbLogger via `_find_wandb_logger`. If None, return early (per D-05). Calls `wandb_logger.experiment.config.update(config_data)`. The `logger.experiment` property returns the raw `wandb.Run` object.

    4. `_log_results_to_wandb(*, results_summary: dict[str, Any], timing: dict[str, float], loggers: tuple[pl.loggers.LightningLogger, ...]) -> None`:
       Finds WandbLogger. If None, return early.
       - Flattens `results_summary` via `_flatten_dict` with `_` separator.
       - Creates timing keys: `{"timing_" + k: v for k, v in timing.items()}`.
       - Calls `run.log({**flat_results, **flat_timing})`.
       - Builds `wandb.Table` from flattened results (per D-06 table). Columns: `experiment`, `dataset`, `seed`, `model_name`, `classification_clean_accuracy`, `classification_clean_f1`, `forecasting_clean_mae`, `geometry_centroid_margin`, `shift_mean_l2`, `total_seconds`.
       - Table row values are extracted from `flat_results` using `.get()` with `None` defaults (keys may not exist depending on pipeline config).
       - Calls `run.log({"comparison": table})`.
       - CRITICAL: Uses `wandb_logger.experiment` to get the run, NOT `wandb.init()` (per RESEARCH.md Pitfall 1).

    Key constraints:
    - NO `wandb.init()` calls — Lightning's WandbLogger already calls it internally.
    - NO module-level `import wandb` — always lazy inside functions (graceful fallback).
    - Empty loggers tuple must NOT cause crashes — `_log_config_to_wandb` and `_log_results_to_wandb` return early if no WandbLogger found.
    - `log_model=False` is explicit (D-07).
