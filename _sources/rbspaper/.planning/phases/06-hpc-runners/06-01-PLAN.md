  #
  # hpc_config.sh — HPC cluster configuration.
  #
  # Copy this file to hpc_config.sh and set the variables below.
  # Do NOT commit hpc_config.sh (it is gitignored).

  # QoS level
  HPC_QOS="medium"

  # Delete job files after submission (true/false)

  Create two Tier 1 scripts. Both are Bash 3.2 compatible (no declare -A, no (( )) on unbound vars, no [[ =~ ]]). Both use `set -uo pipefail` and a `log()` helper. Both detect project root via BASH_SOURCE traversal (same pattern as local_single.sh: go two levels up from runners/bash/).

  Shared bootstrap (both scripts):
  1. Project root: `SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" || exit 1; pwd) || exit 1; PROJECT_ROOT=$(cd "$SCRIPT_DIR/../.." || exit 1; pwd) || exit 1`
  2. Guard: `if [ ! -f "$PROJECT_ROOT/pyproject.toml" ]; then echo "[ERROR] ..." >&2; exit 1; fi`
  3. `log() { echo "[$(date '+%H:%M:%S')] $*"; }`
  4. Config management — source BOTH config.sh (Phase 5, DATA_ROOT) and hpc_config.sh (HPC_OUTPUT_ROOT, cluster params). Auto-copy from .example on first run for both. Exit with error if HPC_OUTPUT_ROOT is empty after sourcing.
  5. Experiment validation: `uv run python -c "from experiment_instances.instances import list_experiment_ids; exit(0 if sys.argv[1] in list_experiment_ids() else 1)" "$exp_id"`
  6. Numeric validation for seed/num_runs: `echo "$SEED" | grep -qE '^[0-9]+$'` (Bash 3.2 compatible).

  --- hpc_submit.sh ---

  Usage: `hpc_submit.sh <experiment_id> --families <family> [--seed N] [--num_runs N] [--force] [--dry_run] [--delete_job_files]`

  After bootstrap + argument parsing:

  7. Resolve dataset count from family:
     ```bash
     TOTAL_DATASETS=$(uv run python -c "
     import sys
     from src.rbspaper.data.data_setup import get_datasets_names
     datasets = get_datasets_names(sys.argv[1], form='list')
     if not datasets:
         print('ERROR: No datasets for family ' + sys.argv[1], file=sys.stderr)
         sys.exit(1)
     print(len(datasets))
     " "$family")
     ```

  8. Per-seed loop: for s from 0 to num_runs-1, compute `run_seed=$((seed + s))`.

  9. Generate SLURM array script via heredoc (unquoted EOL delimiter). Job file: `${HPC_OUTPUT_ROOT}/jobs/hpc_${exp_id}_s${run_seed}.sh`.

     Generation-time (unescaped): exp_id, DATA_ROOT, HPC_OUTPUT_ROOT, run_seed, PROJECT_ROOT, family, force_arg, all HPC_* vars.
     Runtime (escaped with \$): \$SLURM_ARRAY_TASK_ID.

     Array directive: `#SBATCH --array=0-$((TOTAL_DATASETS - 1))%${HPC_MAX_CONCURRENT}`.

     Dataset resolution inside generated script:
     ```bash
     dataset_name=\$(uv run python -c "
     import sys
     from src.rbspaper.data.data_setup import get_datasets_names
     datasets = get_datasets_names(sys.argv[1], form='list')
     print(datasets[int(sys.argv[2])])
     " "\$family" "\$SLURM_ARRAY_TASK_ID")
     ```

     Runner command inside generated script:
     ```bash
     uv run python "\${PROJECT_ROOT}/runners/py/runner.py" \
         --experiment_id="${exp_id}" \
         --dataset_name="\$dataset_name" \
         --data_root="${DATA_ROOT}" \
         --output_dir="\${HPC_OUTPUT_ROOT}" \
         --seed=${run_seed}${force_arg}
     ```
     No --forecasting_mode (batch engine is family-specific; forecasting_mode passed by wrappers to hpc_submit_single.sh).

     PYTHONPATH: `export PYTHONPATH="\${PROJECT_ROOT}:\${PYTHONPATH:-}"`

  10. QoS retry: 3 attempts, backoff 10s → 20s → 40s. Parse sbatch stderr for QOSMaxSubmitJobPerUserLimit or Job violates accounting/QOS policy. On other errors, fail immediately.

  11. --dry_run: generate script, print path, skip sbatch.

  12. Job file cleanup based on DELETE_JOB_FILES config (default false).

  13. Submission report after all seeds.

     Job name: `#SBATCH --job-name=hpc_${exp_id}_${dataset_name}_s${run_seed}`

     Runner command inside generated script:

         --data_root="${DATA_ROOT}" \
         --output_dir="\${HPC_OUTPUT_ROOT}" \
         --seed=${run_seed}${force_arg}${forecasting_mode_arg}

  10. QoS retry, --dry_run, job file cleanup: same pattern as hpc_submit.sh.

  11. Submission report (single dataset version).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → SLURM script | User-provided experiment_id, dataset_name, family, seed injected into generated bash; must not enable shell injection |
| hpc_config.sh → SBATCH directives | Config values used as SBATCH parameters; trusted since user-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-06-01 | Injection | experiment_id CLI arg → heredoc | mitigate | Validate against list_experiment_ids() whitelist before use in heredoc; reject if not found |
| T-06-02 | Injection | family CLI arg → heredoc (hpc_submit.sh) | mitigate | Validate against DATASET_REGISTRY family set via Python one-liner before use |
| T-06-03 | Injection | dataset_name CLI arg → heredoc (hpc_submit_single.sh) | mitigate | Validate via get_dataset_metadata(dataset_name) before use; reject if not in registry |
| T-06-04 | Injection | seed/num_runs args | mitigate | Numeric validation: `echo "$SEED" \| grep -qE '^[0-9]+$'` before use in arithmetic |
| T-06-05 | Spoofing | hpc_config.sh contents | accept | Config is user-controlled; no external trust boundary. User sets own cluster params. |
| T-06-06 | Information Disclosure | Job files in outputs/ | mitigate | Job files contain paths and experiment IDs only — no secrets. HPC_OUTPUT_ROOT and DATA_ROOT are local paths. |
| T-06-07 | DoS | --delete_job_files on failure | mitigate | Default DELETE_JOB_FILES=false. Job files retained unless explicitly requested. |
</threat_model>
