Forecasting time features (ETT, Weather, Electricity) were built from timestamps divided by 1000: the cached datetime index was saved in microseconds and read back as nanoseconds, so after `setup()` every date fell in January 1970 and the 7 time-feature channels were near-constant. The index is now stored and read in nanoseconds explicitly. Data channels and their scaling are unchanged.
Forecasting sliding-window loaders (`INPUT_TARGET`, `INPUT_ONLY`) counted windows `step` rows apart but started window `n` at row `n` instead of `n * step`, so with the default step (`seq_len`) they only covered the first 1-8% of each split. Window `n` now starts at row `n * step`, and the forecasting window count is `(length - seq_len - horizon) // step + 1`, which also restores a last window that was dropped when the split had room for it. `RAW_SERIES` loaders were not affected.
